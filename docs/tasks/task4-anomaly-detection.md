- 오토인코더 + 규칙으로 주입 고장 60건 중 **52건(86.7%)**을 잡았다. 새벽 기준선(심화 2)을 더하면 56건(93%)이다.

- 임계값을 바꾸거나(최선 80%·2.2회), 최근 점수로 기준을 다시 잡아도(72%·2.5회) 두 기준을 함께 넘지 못했다. 여름이 들어간 학습이 필요하다.
- 모델은 **영점 틀어짐**에 약하고, 규칙은 **영점 틀어짐·값 고정·설비 고장**에 약하다. 둘은 서로를 메운다.

## 생각해 볼 점

**Q1. 정상 범위 값에서 멈춘 센서를 모델이 못 알아채는 이유?**

- 오토인코더는 "정상처럼 생긴 값"이면 잘 재구성한다. 정상 범위 안의 평평한 값은 밤·주말에 늘 보던 모양이다.
- 실측
  - 모델이 놓친 값 고정 3건은 모두 사무실 밤(21:35·22:20·02:20 시작)이었다.
  - 낮에 시작한 값 고정은 이웃 센서가 움직이는데 혼자 그대로라 잡혔다.
  - 고정이 "이상"이 되는 것은 **주변이 변할 때뿐**이다.
- 그래서 규칙이 이웃 비교를 쓴다. 그래도 밤에는 이웃도 변하지 않아 규칙도 놓친다(1/12).
- 운영 제안: 밤에 4시간 넘게 그대로면 아침에 한 번 알린다([③](../deliverables/task4/03-operations.md)). 과제 8 서비스의 `stuck` 규칙과 데이터 끊김 경보가 이 빈틈을 일부 메운다.

**Q2. 빈 방에서 환기가 멈추면 탐지할 수 있나? 필요한가?**

- **데이터로는 거의 불가능하다.** 환기 정지의 신호는 "사람이 내는 CO₂가 빠지지 않음"이다. 사람이 없으면 CO₂가 오르지 않아 정상과 같은 모양이 된다. 그래서 주입도 사용 중에만 했다(README 정의: 사용 중 상승 폭 1.8배).
- **급히 탐지할 필요도 작다.** 빈 방에는 노출될 사람이 없다.
- 다음에 사람이 들어오면 바로 드러난다. 사용 중 환기 정지는 결합 탐지기가 12/12, 지연 중앙 0분으로 잡았다.
- 사람이 오기 전에 미리 알고 싶다면 센서가 아니라 **설비 상태(xflow 환기·냉난방 운전 신호)**를 봐야 한다. 과제 1이 2026-10-20부터 xflow를 수집하고 있다.

**Q3. 실데이터에는 정답이 없다. 탐지기가 잘 동작하는지 어떻게 확인하나?**

1. **주입 시험**: 실제 데이터에 정의된 고장 5종을 넣어 정답을 만든다. 이번 평가가 이 방식이다. 새 계절마다 다시 돌린다.
2. **검증 기간의 경보율**: 고장이 거의 없다고 보는 기간에서 하루 경보 수를 잰다. 이번에 검증 0.47 → 시험 4.65로 크게 달라진 것 자체가 "분포가 바뀌었다"는 신호였다.
3. **알려진 사건과 대조**: 과제 2 사건 후보(화재·누수·밀집)와 겹치는 경보를 센다(시험 5건).
4. **사람의 확인 기록**: 운영 중 경보마다 "고장 / 사용 / 모름"을 남기면 한 달 뒤 실제 헛경보율이 나온다(운영 제안).
