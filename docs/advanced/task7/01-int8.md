# 과제 7 심화(B) ① INT8 변환

> **측정 조건**: [최적화 보고서](../../deliverables/task7/01-optimization-report.md)와 같다(25W, 클럭 고정 안 함, 워밍업 50·반복 1,000, TensorRT 10.16.2).
> 보정 표본: **학습 기간**(2025-09-04 ~ 2026-03-31)의 (공간, 기준 시각) 무작위 2,000개(씨앗 0). 시험 기간은 쓰지 않았다. 엔트로피 보정기(`IInt8EntropyCalibrator2`)

## 해석

**INT8로 빌드는 됐지만 실제로는 INT8로 돌지 않았다.**
- 결과 차이가 FP16과 거의 같다. LSTM·TCN은 소수점 넷째 자리까지 같고, GRU 두 모델도 0.1~0.2ppm 안이다. 지연도 같다.
- INT8 엔진을 만들 때 TensorRT는 INT8 구현이 없거나 더 느린 층을 FP16으로 남긴다.
  - GRU·LSTM의 순환 층에는 INT8 커널이 없다.
  - 나머지는 작은 선형층뿐이라, 정밀도를 바꿔도 시간 차이가 나지 않는다(고정 비용 ~1ms가 지배).
  - 그래서 엔진이 사실상 FP16 엔진과 같아졌다.
- TCN은 INT8에서 오히려 p95가 나빠졌다(0.86 → 2.37ms). 합성곱 일부가 INT8로 바뀌면서 정밀도 변환(재포맷) 층이 끼어든 것으로 보인다. 다만 층별 정밀도를 직접 확인하지는 못했다(엔진 상세 정보는 빌드 때 `DETAILED`로 켜야 남는다).

**결론: 이 모델들에 INT8은 이득이 없다.**
- 속도 이득 0, 정확도는 FP16과 같은 이유로 1ppm 기준 불합격이다.
- INT8이 의미 있는 것은 계산이 지연을 지배할 만큼 큰 모델이다. 과제 6의 사전학습 모델(수천만~1억 파라미터)이 후보다.
- 이 보드에서 작은 시계열 모델의 지연을 줄이는 길은 정밀도가 아니라 **GPU 고정 비용을 피하는 것**(ONNX Runtime CPU)이었다.
