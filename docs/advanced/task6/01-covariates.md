# 과제 6 심화(B) ① 공변량을 받는 모델 — Chronos-2에 온습도·시간·일정 넣기

> **측정 조건**: 실데이터, 시험 2026-05-27 ~ 07-22(과제 2·3과 같은 평가 시점), 검증 2026-04-02 ~ 05-09. 추가 학습 없음.
> Chronos-2(1억 2천만 파라미터, 리비전 `29ec3766d3`), **과거 1일(288칸)**, 묶음 32, GPU, 메모리 상한 2.5GB.
> 공변량은 다음 두 가지다.
> - 과거 공변량: 온도·습도(같은 공간 대표값)
> - 미래에도 아는 공변량: 시간대·요일·고정 일과표(과제 3과 같은 특징 함수)
>
> 실행: `pretrained predict val|test --models chronos2 --ctx 1440 [--cov]`

## 해석

**공변량은 실습실에서만 크게 듣는다. 일과표대로 움직이는 공간이라서다.**
- 실습실 CO₂는 수업 시작·점심·퇴실에 맞춰 움직인다(과제 2: 수업 시작 5분 안 반응 99%). "지금이 몇 시이고 수업이 언제 끝나는지"를 알면 60분 뒤를 훨씬 잘 맞힌다.
- 과제 3 입력 단계 실험과 같은 결론이다. GRU에 시간 특징을 더했을 때 실습실 검증 CO₂ 60분이 46.7 → 34.0ppm(−27%)이 됐다.
- 사무실·회의실은 일과표와 실제 사용이 맞지 않아(과제 2: 사무실 점심 반응 37%, 회의실 일정 없음) 공변량 효과가 1~4%에 그친다.

**긴 과거가 공변량을 대신한다.**
- CO₂만 넣고 과거를 **1주**로 늘리면 공변량을 넣은 1일보다 낫다(시험 실습실 41.2 vs 48.8).
- 1주 과거에는 지난 7일의 같은 시각이 다 들어 있다. 모델이 "평일 9시에는 오른다"를 과거에서 직접 읽는다. 시간 특징이 하던 일을 과거 값이 한다.
- 비용이 다르다. 공변량 실행은 CO₂만 실행보다 **9배 느렸다**(시험 1,104초 vs 122초). 과거 1주 + 공변량은 메모리가 상주 서비스를 위협해(여유 121MB까지 감소) 중단했다.

**결론**
- 이 보드에서는 **공변량보다 긴 과거(1주)가 싸고 효과적이다.**
- 공변량이 꼭 필요한 경우는 과거가 짧을 때(새 공간, 수집 시작 직후)와 **미래에만 아는 정보**(회의 예약)다. 회의 예약은 과거 CO₂에 없는 정보다. 실제 예약 기록이 생기면 미래 공변량으로 넣는 것이 회의실을 개선할 유일한 길이다. 과제 3 심화 2에서 추정 예약으로 −28% 상한을 확인했다.
