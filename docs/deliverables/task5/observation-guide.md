# 과제 5 직접 관찰 안내

사용 여부 추정의 확인 기준은 "**직접 관찰한 시간대** 기준 정확도와 F1"이다. 일정(시간표)으로 만든 정답은 실제와 다를 수 있다(결석, 휴강, 연장, 예약 없는 사용). 그래서 일부 시간대를 사람이 직접 보고 기록한다.

## 목표량 (2026-10-21 결정)

| 항목 | 목표 |
|---|---|
| 공간별 수업일 | 실습실·사무실·회의실 각각 **2일 이상** |
| 전체 관찰 시간 | **20시간 이상** |
| 일정 경계 | 09:00 · 11:30 · 13:00 · 18:00 각각 앞뒤 30분을 공간마다 **4회 이상** 포함 |
| 회의실 | 회의 **2회** 이상 + 빈 시간 **2시간** 이상 |
| 인원 | 가능하면 사람 수도 적는다(적은 인원도 센서로 보이는지 확인용) |

경계 시각을 넣는 이유: 사람이 막 들어오거나 나간 직후에 모델이 가장 많이 틀린다(생각해 볼 점 Q1). 그 순간이 기록에 있어야 오류를 잴 수 있다.

## 기록 방법

보드 터미널에서 입력한다(어디서든 동작). Claude Code 대화창에서는 앞에 `!`를 붙인다.

**상태가 바뀔 때마다 한 줄**이면 된다. 직전 상태는 자동으로 닫힌다.

```bash
state observe lab empty --by KW                  # 지금부터 실습실 비어 있음
state observe lab occupied --people 24 --by KW   # 사람이 들어옴(인원 선택)
state observe lab empty --by KW                  # 모두 나감
state observe lab stop                           # 관찰을 끝냄(마지막 구간 닫기)
```

- 공간 이름: `lab`(실습실), `office`(사무실), `meeting`(회의실)
- 상태: `occupied`(사용중, 한 명이라도 있음) / `empty`(비어있음)
- `--by`: 관찰자 **머리글자**(4자 이하). 이름은 쓰지 않는다
- 시각은 기본이 "지금"(KST)이다. 나중에 옮겨 적을 때는 `--at "2026-10-22 09:03"`을 붙인다
- 특이 상황은 `--note`로 남긴다. 예: `--note "창문 열림"`, `--note "문 열어 둠"`, `--note "청소"`

**진행 확인과 점검**

```bash
state observe --status     # 공간별 관찰 시간·수업일 수·경계 포함 횟수·목표 진행률
state observe --check      # 형식·겹침 점검(문제가 있으면 줄 번호와 이유)
state observe --check --door   # + 출입문 센서 보고와 대조('비어있음'인데 문이 열린 구간 표시)
```

## 기록 규칙

- **한 명이라도 있으면 사용중**이다. 잠깐 들른 사람(1분 미만)은 무시해도 된다.
- 직접 보지 못한 시간은 기록하지 않는다. 자리를 비우면 `stop`으로 닫는다.
- 같은 공간을 두 사람이 동시에 기록하지 않는다(구간이 겹치면 기록이 거부된다).
- 기록 파일은 `data/observations.csv`이다. **공개 저장소에 올리지 않는다**(git 제외됨).

## 기록이 쓰이는 곳

- 일정 기반 정답이 실제와 얼마나 다른지(산출물 "일정 기반 정답과 직접 관찰의 차이")
- 사용 여부 분류기의 정확도·F1과 "비어있음인데 사용중으로 판단한 오류율"(확인 기준 1)
- 회의실 판정(회의실은 실제 예약 기록이 없어 관찰로만 판정한다)
- 노쇼·예약 없는 사용 규칙의 검증(심화)
