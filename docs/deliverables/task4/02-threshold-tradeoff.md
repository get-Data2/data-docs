# 과제 4 산출물 ② 임계값과 탐지율·헛경보

> **측정 조건**: [① 성적표](01-scorecard.md)와 같다(실데이터 + 주입 고장 60건, 시험 2026-05-27 ~ 07-22).
> 임계값 선택은 **검증 기간(주입 없음)의 하루 경보 수로만** 했다. 아래 시험 값은 선택이 끝난 뒤 보고용으로 낸 것이다.
> 숫자 원본: [결과 표 ②](tables/02-threshold-curve.md), 적응 임계값 실험 `var/anomaly/adaptive.json`(`anomaly adaptive`)

## 임계값을 어떻게 정했나 (해결할 것 2)

1. 오토인코더 점수를 **검증 기간 점수 분포의 분위수**(0~1)로 바꾼다. 공간마다 점수 크기가 달라 분위수로 맞춘다.
2. 후보 분위수(0.99 ~ 0.99999, 30개) 중 **검증 기간 하루 경보 ≤ 0.5**(전체 공간 합)가 되는 가장 낮은 값을 고른다 → **0.999**(검증 0.47/일).
3. 목표를 0.5로 둔 것은 규칙 경보(검증 0.5~0.9/일)와 합쳐도 하루 1회를 넘지 않게 하려는 것이다.

**헛경보율과의 연결**
- 고장이 거의 없는 기간이라면, 분위수 q로 잡은 기준은 "정상 칸의 (1 − q)가 넘는다"는 뜻이다.
- 0.999는 1,000칸 중 1칸이다. 공간 3곳 × 하루 288칸 = 864칸이므로 대략 하루 0.9칸이 넘는다.
- 30분 안 경보를 하나로 묶으면 검증 0.47건/일이 된다. 정상 분포가 **변하지 않는다**면 헛경보는 이 근처에 머문다.

## 고정 임계값 — 바꿔 보면 (시험, 오토인코더 + 규칙)

![임계값 곡선](figures/threshold_curve.png)

| 임계 분위수 | 검증 경보/일 | 시험 탐지율 | 시험 헛경보/일 |
|---|---|---|---|
| 0.99 | 2.37 | 81.7% | 9.12 |
| 0.995 | 1.29 | 90.0% | 8.56 |
| 0.998 | 0.66 | 90.0% | 6.16 |
| **0.999(선택)** | **0.47** | **86.7%** | **4.65** |
| 0.9995 | 0.26 | 85.0% | 3.32 |
| 0.9998 | 0.16 | 80.0% | 2.18 |
| 0.9999 | 0.11 | 75.0% | 1.96 |
| 0.99999(최대) | 0.08 | 68.3% | 1.89 |

- 임계값을 올리면 헛경보가 줄지만 **1.89회/일 아래로는 내려가지 않는다.** 규칙 경보(0.65/일)와 매우 높은 점수의 모델 경보가 바닥에 남는다.
- 가장 높은 기준에서도 회의실 회의 시작처럼 "정말 드문" 정상 사건이 남는다.
- **검증에서 0.47회였던 기준이 시험에서 10배가 됐다.** 기준을 잘못 정한 것이 아니다. 정상 분포 자체가 바뀌었다는 뜻이다([①](01-scorecard.md) "헛경보 원인").

## 분포 이동에 맞서기 — 적응 임계값 실험

모두 **인과적**이다(그 날 이전 점수만 씀). 분위수 기준값은 검증 기간에서만 골랐다.

| 방식 | 기준 기간 | 검증 경보/일 | 시험 탐지율(결합) | 시험 헛경보/일(결합) |
|---|---|---|---|---|
| 고정(현재) | 검증 기간 | 0.47 | **86.7%** | 4.65 |
| 중앙값 나눔: 점수 ÷ 최근 N일 점수 중앙값 | 7일 | 0.47 | 70.0% | 2.35 |
| | 14일 | 0.47 | 71.7% | 2.46 |
| | 28일 | 0.47 | 75.0% | 2.51 |
| 최근 N일 분위수로 매일 다시 잡기 | 7일 | 0.74 | 53.3% | 0.84 |
| | 14일 | 0.62 | 48.3% | **0.81** |
| | 28일 | 0.50 | 46.7% | 0.77 |

- **두 확인 기준을 함께 넘는 설정은 없었다.** 헛경보를 1회 아래로 내리면 탐지율이 절반으로 떨어진다.
- 중앙값 나눔은 계절에 따른 점수 수준 이동을 빼서 헛경보를 절반(4.65 → 2.5)으로 줄였다.
  - 대가로 영점 틀어짐(8 → 5/12)·냉방 정지(12 → 9/12)를 놓쳤다. 둘 다 "수준이 서서히 바뀌는" 고장이라, 수준 보정이 일부를 함께 지운다.
- **그러나 고정 임계값을 0.9998로 올린 것(80.0%, 2.18/일)보다 못하다.** 적응 방식이 더 나은 점은 없었다.
- 최근 분위수 방식은 "최근 2주 최댓값 수준"을 넘어야 경보한다. 그래서 지난 고장·회의가 기준을 끌어올려 다음 고장을 가린다.
- **경보를 오래 지속될 때만 내는 방법도 효과가 없다.**
  - 진짜 탐지도 59%가 한 칸(5분)짜리 경보였다(헛경보는 64%).
  - 10분 이상만 남기면 헛경보가 0.89/일이 되지만 탐지율이 37%로 떨어진다.

## 결론과 행동

- 이 오토인코더는 **학습한 계절 밖에서는 기준이 맞지 않는다**. 임계값만 손봐서는 두 기준을 함께 만족할 수 없었다. 가장 좋은 지점도 탐지 80%·헛경보 2.2회/일이다.
- **근본 해결은 여름 데이터로 다시 학습하는 것이다.** 이제 InfluxDB 적재로 2026-07~10 데이터가 있다.
  - 2학기 분할(`v2-final`)로 학습 기간에 여름을 넣으면 같은 계절 이동이 사라진다.
  - 그때 검증 기준(하루 0.5회)이 시험에서도 유지되는지 다시 잰다. 과제 2 `v2-final`과 함께 하는 다음 작업이다.
- 그 전까지 운영 기준은 **0.9998**을 권한다(탐지 80%, 헛경보 2.2회/일).
  - ⚠️ 이 값은 시험 결과를 보고 고른 것이라 **공정한 성능 수치가 아니다**. 운영 설정 제안일 뿐이다.
  - 공식 판정은 검증으로 고정한 0.999 결과(86.7%, 4.65/일)다.
