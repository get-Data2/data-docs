# 과제 4 산출물 ① 탐지 성적표

> **측정 조건**
> - **실데이터 + 주입 고장**: 시험 기간 2026-05-27 ~ 07-22(57일)의 센서 5분 시계열 사본에 고장 5종 × 12건 = 60건을 주입했다.
>   - 씨앗 42, 정답 표 sha256 `cd462893e1fa725b…`, 바뀐 칸 6,537개
> - 학습: 2025-09-04 ~ 2026-03-31 **정상만**(과제 2 사건 후보·값 고정 후보 제외). 공간별 오토인코더, Jetson Orin Nano Super GPU(25W)
> - 임계값: 검증 2026-04-02 ~ 05-09(주입 없음)에서 **하루 경보 ≤ 0.5**가 되는 가장 낮은 값으로 고정(sha256 `494e36e8b13a4881…`). 시험 결과는 고정 뒤 한 번 냈다
> - 경보: 30분 안이면 하나로 묶는다. 매칭 여유는 30분(영점 틀어짐은 24시간)
> - 숫자 원본: [결과 표 ①](tables/01-scorecard.md), 다시 만들기 `anomaly evaluate && anomaly report`

## 누가 무엇을 못 잡나 (확인 기준 3)

| 탐지기 | 못 잡는 고장 | 이유(근거) |
|---|---|---|
| **모델** | **영점 틀어짐**(7/12, 지연 80분~11시간) | 오토인코더는 "여러 센서가 같이 움직이는 모양"을 배운다. 하나의 CO₂가 천천히 +200~400ppm 오르면 사람이 들어온 것과 구별되지 않는다. 오차가 서서히 쌓여 늦게 넘는다 |
| | 값 고정(9/12) | 놓친 3건이 모두 사무실 밤(21:35~02:20)이다. 밤에는 정상 값도 거의 안 변한다. 정상 범위 안의 평평한 값은 재구성이 잘 된다(생각해 볼 점 Q1) |
| | 튄 값(8/12) | 놓친 4건은 온도 3건(±3.8~7.8℃)·습도 1건(−22.6%), 모두 한 칸이다. 오토인코더는 1시간(12칸) 창 전체를 재구성하므로 한 칸 오차가 창 평균에 묽어진다. 같은 4건을 규칙은 모두 잡았다 |
| **규칙** | **영점 틀어짐**(0/12) | 급변 규칙은 "한 칸 급변"만 본다. 하루에 걸친 변화는 칸마다 작다 |
| | **값 고정**(1/12) | 규칙은 "같은 공간 다른 센서는 변하는데 이것만 그대로"를 요구한다. 놓친 11건 중 8건이 밤·새벽이라 이웃도 변하지 않았다. 나머지 3건은 퇴실 무렵(17:25~18:05) 시작이다 |
| | 냉방 정지(1/12)·환기 정지(5/12) | 공간 전체가 서서히 변하는 설비 고장이라 급변·고정 어느 쪽 모양도 아니다 |

- **둘을 합치면 서로 메운다.** 규칙은 튄 값(12/12)을 즉시 잡고, 모델은 설비 고장(냉방·환기)을 잡는다.
- **둘 다 약한 것은 영점 틀어짐**(결합 8/12)이다. 그래서 심화 2에서 전용 탐지기를 만들었다. 결합에 더하면 11/12다.

> 수정 기록(2026-10-21): 값 고정 규칙에서 버그를 찾았다.
> - 이웃 센서가 그 시간에 모두 결측이면, 규칙이 "이웃 없음" 규칙으로 넘어가지 않고 건너뛰었다.
> - 시험 결과를 보다 찾은 것이라 사후 수정임을 밝힌다. 규칙 파라미터는 바꾸지 않았다.
> - 고친 뒤 규칙 값 고정이 0/12 → 1/12가 됐다. 결합 탐지율은 변하지 않았다(그 건은 모델이 이미 잡았음).

## 원인 지목 (해결할 것 5)

- 오토인코더: 재구성 오차가 가장 큰 **장치·항목**을 원인으로 낸다(상위 3개). 규칙은 해당 장치를 낸다.
- 원인 정확도(주입한 장치·항목과 일치): 모델 87%, 규칙 94%, 결합 83%다.
  - 냉방 정지(58%)가 낮다. 공간 전체 온도가 오르므로 "어느 한 센서"라는 답이 애초에 맞지 않는다.
  - 이 경우는 원인을 "공간 온도 전체"로 보고하는 것이 맞다(운영 제안 참고).

## 헛경보 4.65회/일 — 원인

| 근거 | 값 |
|---|---|
| 같은 임계값의 검증 기간 헛경보 | **0.47/일** → 시험 3.32/일(모델만) |
| 오토인코더 점수 중앙값(검증 → 시험) | 실습실 17.7 → **69.6**, 사무실 6.8 → **29.3**, 회의실 4.5 → **8.7** |
| 주별 헛경보(모델) | 5월 말 2건 → 7월 셋째 주 **42건**. 여름으로 갈수록 늘어남 |
| 원인 항목 | **습도**가 107/189건(57%). 회의실 습도만 66건 |
| 시각 | 09시 36건, 13시 25건. 회의실 회의 시작 시각 |
| 공간 | 회의실 105 · 사무실 53 · 실습실 31(모델) |

**결론**
- 헛경보가 많은 주원인은 **계절 이동**이다.
  - 모델은 가을·겨울(학습)과 봄(검증)의 습도·온도 수준만 봤다. 여름(시험)의 높은 습도를 "평소와 다름"으로 본다.
  - 과제 3 회의실 온도 예측이 나빠진 것과 같은 원인이다.
- 둘째 원인은 **회의실의 실제 사용**이다. 갑작스러운 CO₂·습도 변화는 고장이 아니라 사용이다. 회의실 규칙 헛경보 31건 중 급변 22건은 모두 평일 낮 사용 시간대였다.
- 임계값만 올려서는 풀리지 않는다. 후보 중 가장 높은 임계값에서도 결합 헛경보가 1.89/일이었다(탐지율 68%). 자세한 것은 [산출물 ②](02-threshold-tradeoff.md)에 있다.

개선 실험과 운영 제안은 [산출물 ②](02-threshold-tradeoff.md)와 [③](03-operations.md)에 있다.
