# Feature Specification: 사전학습 모델 비교 (과제 6)

**Feature Branch**: `006-pretrained-models`

**Created**: 2026-10-21

**Status**: Ready for plan

**Input**: User description: "과제 6 사전학습 모델 비교 (README '과제 6' 전체 + 심화 B 2개). 시계열 파운데이션 모델 1종 이상으로 시험 기간 CO₂ 60분 예측(추가 학습 없음),
기준선 · 직접 학습 모델(과제 3) · 사전학습 모델을 같은 시점에서 비교, 예측 구간(10~90%) 적중률, 보드 추론 시간·메모리, 채택 의견.
심화: 공변량(온습도·일정) 모델 비교, 직접 학습 + 사전학습 섞은 예측."

## 배경 (2026-10-21 기준)

- **평가 기준은 과제 2·3과 같다.**
  - 분할 `v1-provisional`: 학습 2025-09-04 ~ 2026-03-31, 검증 04-02 ~ 05-09, 시험 05-27 ~ 07-22(KST)
  - 평가 시점 파일 `eval_points_v1-provisional`(sha256 `2f878c11d09ab68d…`)의 **CO₂ 행**이 대상이다. 공간은 실습실·사무실·회의실이고 지평은 5·15·30·60분이다.
  - 회의실 5·15분은 과제 2와 같은 이유로 "평가 불가"다.
  - 입력·정답은 관측 칸만 쓴다.
- **비교 대상**
  - 기준선 3종: `baseline_v1-provisional.parquet`
  - 직접 학습 모델: 과제 3 최종 모델의 시험 예측(`selection.json`의 final 그룹, 씨앗 평균)
- **사전학습 모델**: 많은 시계열로 미리 학습해 두고, 과거 값만 주면 바로 예측하는 모델이다. 우리 데이터로 다시 학습하지 않는다.
  후보는 Chronos-Bolt(tiny·mini·small)와 공변량을 받는 Chronos-2다. 패키지 `chronos-forecasting` 2.3.2는 보드(aarch64)에 설치 가능함을 확인했다.
- **실행 환경**
  - Jetson Orin Nano Super(25W), RAM 7.3GB를 CPU·GPU가 함께 쓴다. 외부망 와이파이로 HuggingFace 다운로드가 가능하다.
  - 같은 보드에서 다른 계정(t2) 프로세스가 약 1GB를 쓰는 것을 관찰했다(2026-10-21).
  - `tegrastats`(전력·GPU·메모리)는 sudo 없이 동작한다. 클럭 고정(`jetson_clocks`)은 sudo가 필요해 **할 수 없다**.
  - 과제 3 학습이 GPU를 쓰는 동안에는 성능 측정을 하지 않는다.

## 용어

| 용어 | 뜻 |
|---|---|
| 사전학습 모델 | 미리 학습된 시계열 예측 모델. 추가 학습 없이(제로샷) 쓴다 |
| 컨텍스트 | 모델에 주는 t0 이전 과거 값 구간 |
| 예측 구간 | 모델이 내는 분위수 예측 중 10%~90% 사이. 실제 값이 이 안에 들어오는 비율이 **적중률**이고, 이상적이면 80%다 |
| 공변량 | 예측 대상(CO₂) 말고 함께 넣는 변수. 온도·습도(과거), 시각·요일·일과표(미래까지 알 수 있음) |
| 섞은 예측(앙상블) | 직접 학습 모델과 사전학습 모델 예측의 가중 평균 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 같은 시점에서 세 방법을 비교한다 (Priority: P1)

분석가는 사전학습 모델로 시험 기간 CO₂를 예측하고, 기준선·직접 학습 모델과 같은 평가 시점·같은 정답으로 비교표를 얻는다.

**Why this priority**: 해결할 것 1·2번과 확인 기준 1번이다.

**Independent Test**: 명령 하나로 평가 시점 파일의 CO₂ 행 전부에 사전학습 예측이 붙고, 세 방법의 MAE가 한 표에 나온다. 표의 평가 시점 수는 기준선 표와 같다.

**Acceptance Scenarios**:

1. **Given** 평가 시점 파일, **When** 사전학습 모델로 예측하면, **Then** CO₂ 행마다 예측(중앙값)과 분위수(10·50·90%)가 생긴다. 파일 해시가 기록된다.
2. **Given** 입력 컨텍스트, **When** 확인하면, **Then** t0 이후 값과 과제 2 보간 칸은 들어가지 않는다(인과적 입력).
3. **Given** 세 방법의 예측, **When** 비교표를 만들면, **Then** 공간 × 지평(5·15·30·60)마다 기준선 3종 · 직접 학습 · 사전학습의 MAE가 전체·사용 시간대로 나란히 나온다.
4. **Given** 사전학습 모델 크기 여러 개(tiny·mini·small 등), **When** 비교하면, **Then** 크기별 정확도와 비용이 함께 나온다.

---

### User Story 2 - 예측 구간이 얼마나 맞는지 확인한다 (Priority: P1)

운영자는 "10~90% 범위"를 믿어도 되는지 알고 싶다.

**Why this priority**: 해결할 것 3번이다.

**Independent Test**: 공간 × 지평마다 적중률(목표 80%)과 구간 평균 폭이 나온다.

**Acceptance Scenarios**:

1. **Given** 분위수 예측, **When** 적중률을 계산하면, **Then** 공간 × 지평 × (전체·사용 시간대) 적중률, 아래로 벗어난 비율, 위로 벗어난 비율, 평균 폭(ppm)이 나온다.
2. **Given** 적중률이 80%에서 벗어남, **When** 해석하면, **Then** 구간이 너무 좁은지(과신) 너무 넓은지, 어느 순간(수업 시작 등)에 벗어나는지 적는다.

---

### User Story 3 - 보드에서 비용을 잰다 (Priority: P1)

운영자는 보드에서 한 번 예측하는 데 걸리는 시간과 메모리를 알고 싶다.

**Why this priority**: 해결할 것 4번과 확인 기준 2번(정확도·적중률·시간·메모리 네 가지 근거)이다.

**Independent Test**: 모델 × 장치(GPU·CPU) × 배치(1, 3공간)마다 지연(평균·느린 쪽 5%), 메모리, 전력이 측정 조건과 함께 나온다.

**Acceptance Scenarios**:

1. **Given** 모델, **When** 지연을 재면, **Then** 워밍업 뒤 정해진 반복 횟수로 평균과 p95(ms)가 나온다.
2. **Given** 측정 중, **When** 자원을 기록하면, **Then** 프로세스 최대 메모리(RSS)·GPU 할당·보드 전력(VDD_IN 평균)이 나온다.
3. **Given** 과제 3 직접 학습 모델, **When** 같은 방법으로 재면, **Then** 두 방식의 비용을 한 표에서 비교할 수 있다.
4. **Given** 측정 조건, **When** 결과를 보면, **Then** 전력 모드, 클럭 고정 여부(고정 안 함), 반복·워밍업 수, 동시 실행 작업 여부가 적혀 있다.

---

### User Story 4 - 채택 의견을 낸다 (Priority: P1)

운영자는 사전학습 모델을 서비스(과제 8)에 쓸지 판단하고 싶다.

**Why this priority**: 해결할 것 5번, 산출물(비교표와 채택 의견 반 쪽).

**Independent Test**: 네 근거(정확도·적중률·추론 시간·메모리)로 된 판단표와 반 쪽 의견이 나온다.

**Acceptance Scenarios**:

1. **Given** 비교 결과, **When** 채택 의견을 쓰면, **Then** "주 모델로 채택 / 새 공간·초기용 보조 / 채택 안 함" 중 하나와 네 근거가 나온다.
2. **Given** 로컬 LLM과 공존해야 함, **When** 메모리 예산을 보면, **Then** 가정한 LLM 크기에서 함께 올라갈 수 있는지 표로 나온다.

---

### User Story 5 - 생각해 볼 점에 근거로 답한다 (Priority: P2)

1. **정보 차이(Q1)**: 사전학습 모델은 CO₂ 과거값만 본다. 과제 3의 입력 묶음 실험을 근거로 차이를 나눠 설명한다.
   - "센서값만" 모델 vs "+시간·공간·일정" 모델의 검증 차이(과제 3 D2 단계)
   - 사전학습(CO₂만) vs 과제 3 "센서값만" 모델의 차이
2. **컨텍스트 길이(Q2)**: 1시간·4시간·1일·1주로 비교한다. 선택은 **검증 기간**으로 하고, 시험 결과는 선택한 길이로만 보고한다.
3. **메모리 예산(Q3)**: 로컬 LLM(크기 미정, 가정을 둔다)과 함께 올릴 수 있는지 판단한다.

---

### User Story 6 - 심화(B) (Priority: P3)

1. **공변량 모델**: 공변량을 받는 모델(Chronos-2)에 온도·습도(과거)와 시각·요일·일과표(과거 + 미래 60분)를 넣는다. 같은 모델의 CO₂만 입력과 비교한다.
2. **섞은 예측**: 직접 학습 모델과 사전학습 모델의 가중 평균. 가중치는 **검증 기간** MAE로 정하고(공간 × 지평별 또는 하나), 시험 기간에는 고정 가중치로 한 번 평가한다. 둘 각각보다 나은지 본다.

---

### Edge Cases

- **컨텍스트에 빈 칸이 많음**(회의실 10분 주기, 긴 결측): 모델이 빈 값(NaN)을 받으면 그대로 넣는다. 아니면 앞으로 채운다(research에서 결정). 컨텍스트 관측 비율이 기준 미만이면 "예측 불가"로 두고, 현재값 유지로 대체한 수를 보고한다(과제 3과 같은 규칙).
- **5분 칸 시계열이 아닌 모델 입력 규약**: 모델은 일정 간격 시계열을 받는다. 5분 칸을 그대로 주고 12칸 앞을 예측해 지평 5·15·30·60분을 뽑는다.
- **분위수가 단조가 아님 / 음수 CO₂**: 정렬해 쓰고, 0 미만은 0으로 자른다. 발생 건수를 기록한다.
- **다운로드 실패·버전 변경**: 모델 이름과 리비전(커밋 해시)을 설정에 고정하고 기록한다. 받은 가중치는 보드에 두어 오프라인으로 다시 실행할 수 있게 한다.
- **GPU 메모리 부족**: 배치를 줄여 재시도하고 기록한다. CPU 결과는 따로 낸다.
- **과제 3 결과가 아직 없음**: 비교표의 직접 학습 열은 과제 3 시험 평가 뒤에 채운다. 사전학습 예측·비용은 먼저 할 수 있다.

## Requirements *(mandatory)*

### Functional Requirements

**데이터와 평가 규칙(과제 2·3 승계)**

- **FR-001**: 평가 대상은 평가 시점 파일의 CO₂ 행이다. 시작 시 해시를 확인하고 결과에 기록한다. 다르면 멈춘다.
- **FR-002**: 컨텍스트는 과제 2 공간 시계열의 관측 칸만으로, t0 이전 값만 쓴다(인과적).
- **FR-003**: 정답·지표 계산은 과제 3과 같은 함수 규칙을 쓴다. 공간 × 지평 MAE, 전체·사용 시간대, `min_points` 미만은 "평가 불가"다.
- **FR-004**: 시험 기간 정보는 어떤 선택(모델 크기·컨텍스트 길이·앙상블 가중치)에도 쓰지 않는다. 선택은 검증 기간으로 하고, 선택 파일을 고정한 뒤에만 시험 평가를 한다.

**사전학습 예측**

- **FR-010**: 사전학습 모델 1종 이상(기본: Chronos-Bolt 크기 3종)으로 추가 학습 없이 예측한다. 출력은 12칸 × 분위수(최소 10·50·90%)다.
- **FR-011**: 모델 이름·리비전·파라미터 수·장치·정밀도(fp32/bf16 등)를 기록한다. 가중치는 보드에 저장해 오프라인 재실행이 되게 한다.
- **FR-012**: 컨텍스트 길이는 설정값이다. 후보는 1시간·4시간·1일·1주다.

**예측 구간**

- **FR-020**: 10~90% 구간 적중률, 아래·위 이탈률, 평균 폭을 공간 × 지평 × (전체·사용 시간대)로 낸다.

**비용**

- **FR-030**: 지연은 워밍업(기본 10회) 뒤 반복(기본 100회)한다. 평균·p95(ms)를 배치 1과 배치 3(세 공간)으로 GPU·CPU 각각 잰다.
- **FR-031**: 측정 중 프로세스 최대 RSS, GPU 최대 할당, `tegrastats`의 VDD_IN·VDD_CPU_GPU_CV 평균, GPU 사용률을 기록한다.
- **FR-032**: 같은 방법으로 과제 3 최종 모델(모델 묶음)의 비용을 잰다.
- **FR-033**: 측정 조건을 함께 기록한다: 전력 모드(nvpmodel), 클럭 고정 안 함, 반복·워밍업 수, 동시 실행 프로세스(자기 것 외 GPU 작업 여부).

**판단·보고**

- **FR-040**: 비교표(기준선 3 · 직접 학습 · 사전학습 크기별)와 판단표(정확도·적중률·지연·메모리)를 만든다.
- **FR-041**: 메모리 예산표: 보드 7.3GB에서 OS·수집기·다른 계정 작업 관찰값, 가정 LLM 크기, 시계열 모델들의 합을 비교한다.
- **FR-042**: 채택 의견(반 쪽)을 `docs/deliverables/task6/`에, 심화 결과를 `docs/advanced/task6/`에, 점검 문서를 `docs/tasks/task6-pretrained-models.md`에 둔다.

**심화**

- **FR-050**: 공변량 모델: 같은 모델에 공변량 있음/없음을 비교한다. 공변량은 온도·습도(과거)와 시각·요일·공휴일·일과표(과거 + 미래 12칸)다.
- **FR-051**: 섞은 예측: w·직접 + (1−w)·사전학습. w는 검증 기간 MAE 최소로 정한다(0~1, 0.1 간격). 시험 결과와 두 단독 모델을 비교한다.

**재현**

- **FR-060**: 모든 단계는 설정 파일과 명령으로 다시 실행할 수 있다. 예측 파일·비용 측정 기록에 설정 해시와 입력 해시를 남긴다.

### Key Entities

- **사전학습 모델 기록**: 이름, 리비전, 파라미터 수, 정밀도, 장치, 다운로드 위치·해시
- **예측**: (공간, t0, 지평) → 분위수 10·50·90%(+ 평균), 컨텍스트 길이, 예측 불가 표시
- **비용 측정**: 모델 × 장치 × 배치 → 지연 평균·p95, 최대 RSS, GPU 할당, 전력 평균, 측정 조건
- **선택 파일**: 검증 기간 기준 모델 크기·컨텍스트 길이·앙상블 가중치, 고정 시각·해시
- **판단표**: 네 근거와 채택 의견

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 세 방법(기준선·직접 학습·사전학습)이 **같은 평가 시점**(행 단위 일치)에서 비교된다. 평가 시점 수가 기준선 표와 같다.
- **SC-002**: 판단 근거 네 가지(정확도 MAE, 구간 적중률, 1회 추론 지연 평균·p95, 메모리)가 모델별로 표에 다 채워진다.
- **SC-003**: 적중률이 공간 × 지평마다 나오고, 80%와의 차이를 해석한다.
- **SC-004**: 컨텍스트 길이·모델 크기·앙상블 가중치를 시험 기간 없이 골랐음을 기록과 자동 시험으로 보인다.
- **SC-005**: 채택 의견이 반 쪽 이내이고, 네 근거와 메모리 예산을 인용한다.
- **SC-006**: 모든 결과표에 측정 조건(데이터 기간, 실데이터, 시험 기간, 전력 모드, 클럭 고정 안 함, 반복·워밍업)이 붙는다(헌법 V).

## Assumptions

- 사전학습 모델의 가중치는 공개 HuggingFace 저장소에서 받는다. 받은 뒤에는 오프라인으로 돈다. 라이선스를 기록한다.
- 로컬 LLM(W4)의 크기는 아직 정해지지 않았다. 기본 가정은 "4B급 4비트 양자화, 약 3GB"이고 사용자 확인 항목이다.
- 과제 3 최종 모델 결과가 직접 학습 열의 원천이다. 과제 3 시험 평가가 끝나야 비교표가 완성된다.
- 성능(지연·전력) 측정은 과제 3·4 학습이 끝난 뒤, 보드가 비교적 한가할 때 한다. 다른 계정 작업은 막을 수 없으므로 관찰값을 기록한다.
- 지평 4개를 모두 표에 싣되, README의 판단 대상은 60분이다.
