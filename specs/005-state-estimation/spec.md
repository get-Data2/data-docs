# Feature Specification: 상태 추정 (과제 5)

**Feature Branch**: `005-state-estimation`

**Created**: 2026-10-21

**Status**: Ready for plan

**Input**: User description: "과제 5 상태 추정 (README '과제 5' 전체 + 심화 B 2개). 사용 여부 추정(사용중/비어있음)과 환기 선제 경보(30분 안에 1,000ppm 초과).
정답 정의(일정 기반 + 직접 관찰, 이미 넘은 시점을 정답에 넣으면 안 되는 이유), 입력(사용 여부에 일정 금지), 분류 모델, 불균형 처리,
단순 규칙과 비교. 확인 기준: 관찰 기준 정확도·F1과 '비어있음→사용중' 오류율, 환기 경보 재현율 85% 이상·규칙보다 macro-F1 높음, 혼동 행렬.
심화: 처음 보는 공간, 회의실 노쇼·예약 없는 사용."

## 배경 (2026-10-21 기준)

- **데이터**(과제 2 산출)
  - 공간 5분 시계열 `space_5min`, 센서 5분 시계열 `sensor_5min`
  - 분할 `v1-provisional`(학습 2025-09-04 ~ 2026-03-31, 검증 04-02 ~ 05-09, 시험 05-27 ~ 07-22)
  - 학습 기간 정규화 통계 `norm_v1-provisional.json`, 사건 후보 `events.parquet`
- **일정 자료**
  - 실습실·사무실: 고정 일과표(평일 09:00 ~ 11:30, 13:00 ~ 18:00, 한국 공휴일 제외, `config/analysis.yaml`)
  - 회의실: 실제 예약 자료가 없다. 과제 3의 **추정 예약**(`var/forecast/booking_estimated.parquet`, CO₂ 급상승에서 거꾸로 만든 회의 구간 288건)만 있다.
- **일정은 실제 사용과 다르다.** 과제 2 진단에서 실습실은 학습 기간에만 어긋나는 날이 24일(주말 사용 21일, 수업일 무반응 2일), 사무실은 52일이었다.
  그래서 README대로 일부 시간대를 **직접 관찰**해 일정 기반 정답의 오류를 먼저 잰다.
- **직접 관찰은 사람이 한다.** 과거 기간은 관찰할 수 없으므로, 관찰은 **실시간 수집 기간(2026-10-20 ~)**에 사용자·팀이 한다.
  이 구간은 과제 2 사본에 없어서 `analysis extract`로 사본을 갱신해야 한다.
- **보조 신호**: 실습실·사무실·창고에 출입문 센서(WS301, 열림·닫힘 때 보고)가 있다. 사람 출입의 흔적이지만 "방 안에 사람이 있다"와 같지는 않다(research R3).
- **과제 3**: 60분 예측 모델 묶음(`var/forecast/bundle/`)이 있으면 "30분 안 1,000ppm 초과"를 예측값으로도 판정해 분류기와 비교한다(생각해 볼 점 Q4).
- **실행 환경**: Jetson Orin Nano Super(25W), RAM 7.3GB(CPU·GPU 공유, 다른 계정 프로세스와 공유). 학습 메모리 2GB 이하가 목표다.

## 두 분류 문제의 정의

| 문제 | 시점 단위 | 정답(양성) | 입력 | 단순 규칙 |
|---|---|---|---|---|
| **사용 여부** | 공간 × 5분 칸 | 사용중(occupied). 학습·검증·시험은 일정 기반, 최종 확인은 직접 관찰 | 센서값만(CO₂·온도·습도의 수준·변화). **일정·시각·요일 금지** | 최근 15분 CO₂ +30ppm 이상 → 사용중 |
| **환기 선제 경보** | 공간 × 5분 칸 | t 시점 CO₂ < 1,000이고 (t, t+30분] 안에 1,000 이상이 관측됨 | 센서값 + 시간 정보 + 일정 허용 | 현재 CO₂ ≥ 850 → 경보 |

- **이미 1,000ppm 이상인 시점**은 환기 경보의 학습·평가 대상에서 뺀다. 별도 상태("이미 초과")로 둔다.
  - 이 시점을 양성으로 넣으면 "현재 CO₂ ≥ 1,000"이라는 자명한 규칙만으로 재현율이 오른다.
  - 그러면 성적이 "미리 알려 주는 능력"이 아니라 "이미 넘은 것을 보는 능력"을 재게 된다(생각해 볼 점과 해결할 것 1).
- 시점 t의 판단에는 t까지 관측된 값만 쓴다(인과적). 회의실처럼 10분 주기 센서는 "주기 안 직전값"까지만 쓴다.

## 용어

| 용어 | 뜻 |
|---|---|
| 일정 기반 정답 | 실습실·사무실은 일과표의 일정 중 칸 = 사용중, 회의실은 추정 예약 구간 = 사용중 |
| 관찰 정답 | 사람이 기록한 구간(관찰 기록 CSV)의 상태 |
| 비어있음→사용중 오류율 | 관찰상 비어있음인 칸 중 모델이 사용중으로 판단한 비율(냉난방 자동 제어에서 가장 비싼 오류) |
| 이미 초과 | CO₂ ≥ 1,000인 칸. 환기 경보 평가에서 뺀다 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 정답을 정의하고 일정 기반 정답의 오류를 잰다 (Priority: P1)

평가자는 사용 여부의 일정 기반 정답을 만들고, 직접 관찰한 시간대에서 그 정답이 얼마나 틀리는지 먼저 확인한다.
환기 경보 양성은 위 정의로 만든다.

**Why this priority**: 해결할 것 1번. 정답이 틀리면 성적표가 무의미하다. 관찰이 없으면 확인 기준 1을 판정할 수 없다.

**Independent Test**: 명령 하나로 두 정답 표가 나온다. 관찰 기록이 있으면 일정 기반 정답 대비 관찰의 혼동 행렬과 불일치 구간 목록이 나온다.

**Acceptance Scenarios**:

1. **Given** 고정 일과표·추정 예약, **When** 사용 여부 정답을 만들면, **Then** 공간 × 칸마다 사용중/비어있음과 출처(일과표·추정 예약)가 붙는다.
2. **Given** 관찰 기록 CSV, **When** 일정 기반 정답과 비교하면, **Then** 관찰 칸 수, 일치율, 불일치 유형(일정 있는데 비어있음 = 결석·휴강·노쇼, 일정 없는데 사용 = 연장·예약 없는 사용) 표가 나온다.
3. **Given** 공간 시계열, **When** 환기 경보 정답을 만들면, **Then** 칸마다 양성/음성/이미 초과가 붙고, 양성 비율이 기간·공간별로 나온다(예상 1~2%).
4. **Given** 관찰 기록 형식 오류(겹치는 구간, 모르는 공간, 끝 ≤ 시작), **When** 읽으면, **Then** 줄 번호와 이유로 거부한다.

### User Story 2 - 직접 관찰을 기록한다 (Priority: P1)

관찰자(사용자·팀원)는 실습실·사무실·회의실을 지켜보며 사용 여부를 쉽게 기록하고 싶다.

**Why this priority**: 관찰 정답이 확인 기준 1의 기준이다. 기록이 번거로우면 모이지 않는다.

**Independent Test**: 명령으로 상태 변화를 한 줄씩 남기면 관찰 기록 CSV에 구간이 쌓이고, 관찰 현황(공간별 시간, 경계 시각 포함 여부)이 나온다.

**Acceptance Scenarios**:

1. **Given** 관찰 시작, **When** `state observe <공간> occupied|empty [--people N]`을 입력하면, **Then** 그 공간의 직전 구간이 닫히고 새 구간이 열린다(시각은 입력 시각, KST).
2. **Given** 관찰 종료, **When** `state observe <공간> stop`을 입력하면, **Then** 열린 구간이 닫힌다.
3. **Given** 쌓인 기록, **When** `state observe --status`를 보면, **Then** 공간별 관찰 시간, 사용중·비어있음 비율, 일정 경계(09:00, 11:30, 13:00, 18:00 ±30분) 포함 횟수, 목표 대비 진행률이 나온다.

### User Story 3 - 사용 여부 분류기 (Priority: P1)

운영자는 센서값만 보고 공간이 지금 쓰이는지 판단하는 분류기를 원한다. 예약해 놓고 안 쓰는 회의실, 빈 방의 냉난방을 찾는 데 쓴다.

**Why this priority**: 해결할 것 2·3·5번, 확인 기준 1·3번.

**Independent Test**: 학습 기간 일정 기반 정답으로 학습하고 검증으로 선택한 분류기가 시험 기간과 관찰 시간대에서 정확도·F1·비어있음→사용중 오류율·혼동 행렬을 내고, 단순 규칙과 나란히 비교된다.

**Acceptance Scenarios**:

1. **Given** 입력 특징, **When** 목록을 보면, **Then** 일정·시각·요일 특징이 없다. 넣으려 하면 설정 검증이 거부한다(누수 실험 설정만 예외).
2. **Given** 학습·검증 기간, **When** 분류기를 고르면, **Then** 후보(HistGradientBoosting, 로지스틱 회귀, 작은 MLP) 중 검증 macro-F1이 가장 높은 것을 고르고 선택을 고정한다. 그 뒤에만 시험·관찰 평가가 동작한다.
3. **Given** 관찰 기록, **When** 평가하면, **Then** 관찰 칸 기준 정확도·F1·비어있음→사용중 오류율과 혼동 행렬이 나오고, 단순 규칙보다 F1이 높은지 판정된다.
4. **Given** 시험 기간(관찰 없음), **When** 평가하면, **Then** 일정 기반 정답 기준 같은 지표가 나온다. 일정 기반 정답의 오류율(US1)을 함께 적는다.
5. **Given** "일정 입력 포함" 비교 실험, **When** 같은 방식으로 학습하면, **Then** 일정 기반 정답 기준 성적은 오르지만 관찰 기준(일정과 실제가 다른 칸)에서는 나빠지거나 그대로임을 보인다. 정답을 일정에서 만들고 입력에도 넣으면 모델이 일정을 베낀다는 설명의 근거가 된다(해결할 것 2).

### User Story 4 - 환기 선제 경보 분류기 (Priority: P1)

공간 사용자는 "지금은 괜찮지만 30분 안에 1,000ppm을 넘을 것"을 미리 알고 싶다.

**Why this priority**: 해결할 것 3·4·5번, 확인 기준 2·3번.

**Independent Test**: 시험 기간에서 재현율·정밀도·macro-F1·PR 곡선·혼동 행렬이 나오고, 재현율 ≥ 85%와 단순 규칙 대비 macro-F1 판정이 자동으로 나온다.

**Acceptance Scenarios**:

1. **Given** 양성 1~2%의 불균형, **When** 성적을 내면, **Then** "항상 음성" 분류기의 정확도(약 98%)를 함께 보여 정확도가 무의미함을 보인다.
2. **Given** 검증 기간, **When** 경보 임계값을 정하면, **Then** 검증 재현율 ≥ 85%를 만족하는 임계값 중 정밀도가 가장 높은 값을 고르고 고정한다. 시험 기간 정보는 쓰지 않는다.
3. **Given** 시험 기간, **When** 평가하면, **Then** 재현율 ≥ 85%, 단순 규칙(현재 CO₂ ≥ 850)보다 macro-F1이 높은지 판정한다.
4. **Given** 과제 3 모델 묶음, **When** "예측 30분 안 최댓값 ≥ 1,000"으로 판정하면, **Then** 같은 시점·같은 지표로 분류기와 비교된다(생각해 볼 점 Q4).
5. **Given** 경보, **When** 실제 초과 시각과 비교하면, **Then** 경보가 초과보다 몇 분 먼저 울렸는지(선행 시간) 분포가 나온다.

### User Story 5 - 가장 많이 틀리는 상황 분석 (Priority: P2)

운영자는 분류기가 어떤 시간대·공간·상황에서 틀리는지, 왜 그런지 알고 싶다.

**Why this priority**: 확인 기준 3번, 산출물 3번, 생각해 볼 점 Q1·Q2·Q3.

**Independent Test**: 오류를 시간대·공간·상황(퇴실 직후, 입실 직후, 적은 인원, 창문 개방 추정)으로 나눈 표와 대표 사례 그래프가 나온다.

**Acceptance Scenarios**:

1. **Given** 사용 여부 오류, **When** 상태 전환 시각(일정 경계·관찰 전환) 기준으로 나누면, **Then** 전환 뒤 0 ~ 60분 구간별 오류율이 나온다. 퇴실 직후(사용중으로 오판)와 입실 직후(비어있음으로 오판)의 지연이 숫자로 나온다(Q1).
2. **Given** 관찰 기록의 인원 수, **When** 인원별로 나누면, **Then** 적은 인원(예: 1 ~ 3명) 구간의 재현율이 따로 나온다. 공간 부피 대비 CO₂ 상승 속도가 구별 가능성을 정한다는 해석을 쓴다(Q2).
3. **Given** 환기 경보 헛경보, **When** 하루당 수와 사례를 보면, **Then** 정밀도가 낮을 때 현장에서 생기는 일(알림 피로)과 재현율 우선 근거를 쓴다(Q3).

### User Story 6 - 심화(B) (Priority: P3)

1. **처음 보는 공간**: 공간 하나를 학습·검증에서 완전히 빼고(정규화도 학습 공간 통계만), 그 공간의 사용 여부를 추정한다. 포함 학습과의 성적 차이로 "새 공간에 바로 쓸 수 있는가"를 답한다.
2. **회의실 노쇼·예약 없는 사용**
   - 예약 구간 시작 뒤 15분간 추정 사용 여부가 비어있음이면 **노쇼**
   - 예약 밖에서 추정 사용중이 정해진 시간(예: 15분) 이상 이어지면 **예약 없는 사용**
   - 이 규칙을 만든다. 실제 예약 자료가 없고, 추정 예약은 CO₂에서 만들어 사용 여부 추정과 **순환 논리**다.
     그래서 규칙의 성능은 **관찰 기록(또는 실제 예약 CSV를 받은 뒤)으로만** 검증한다고 명시한다. 관찰이 없으면 규칙 동작 예시만 보인다.

### Edge Cases

- **관찰 기록이 없거나 적음**: 관찰 기준 판정은 "판단 보류"로 적고, 일정 기반 정답 기준 결과만 낸다. 관찰 목표량(research R2)과 진행률을 함께 보고한다.
- **관찰 구간이 실시간 기간(2026-10-20 ~)**: 학습·선택은 과거 분할로 하고, 관찰 구간은 평가에만 쓴다. 사본 갱신(`analysis extract`) 뒤 평가한다.
- **일정과 관찰이 다른 칸**: 학습 정답(일정)으로는 고치지 않는다. 관찰 평가와 오류 분석에서 따로 센다.
- **회의실 10분 주기**: 칸의 절반이 주기 안 직전값이다. 특징은 관찰 칸 기준으로 만든다.
- **결측 구간**: 입력 관측 비율이 기준 미만이면 그 칸은 "판단 불가"로 두고 지표에서 빼며 수를 보고한다.
- **이미 초과 상태가 길게 이어짐**: 이 칸들은 환기 경보에서 빠진다. 초과가 끝나고 다시 오를 때의 칸은 평가 대상이다.
- **공휴일·방학**: 일정 기반 정답은 비어있음이다. 실제 사용은 관찰·오류 분석에서 드러난다.

## Requirements *(mandatory)*

### Functional Requirements

**정답**

- **FR-001**: 사용 여부 일정 기반 정답은 실습실·사무실은 고정 일과표, 회의실은 추정 예약(또는 설정의 실제 예약 CSV)에서 만든다. 출처를 칸마다 남긴다.
- **FR-002**: 관찰 기록 CSV(`data/observations.csv`: space_id, start, end, state, people, observer, note)를 읽고 검증한다. 형식 오류는 줄 번호와 함께 거부한다.
- **FR-003**: 관찰 대비 일정 기반 정답의 혼동 행렬과 불일치 유형·구간 목록을 낸다.
- **FR-004**: 환기 경보 정답: t 시점 CO₂ < 1,000이고 (t, t+30분] 안에 관측된 CO₂ 최댓값 ≥ 1,000이면 양성. CO₂ ≥ 1,000인 칸은 "이미 초과"로 학습·평가에서 뺀다. 기준값·창 길이는 설정이다.

**관찰 보조**

- **FR-010**: `state observe`로 상태 전환을 한 줄씩 기록하고, 열린 구간을 닫고, 현황(관찰 시간·경계 포함 횟수·목표 진행률)을 보여 준다.

**입력**

- **FR-020**: 사용 여부 입력은 센서값에서만 만든다. 최근 창(기본 30분)의 CO₂·온도·습도 수준, 변화량(5·15·30분), 기울기, 이동 표준편차, 공간 정규화 값을 쓴다.
  일정·시각·요일 특징은 금지하고 설정 검증이 거부한다. 단, 누수 비교 실험(`with_schedule`)만 예외다.
- **FR-021**: 환기 경보 입력은 위 센서 특징 + 시간 정보(시각·요일·공휴일) + 일정 상태·다음 일정 변화까지 남은 시간을 허용한다.
- **FR-022**: 모든 입력은 인과적이다(t까지의 관측만). 과제 3 R4와 같이 관측 칸만 쓰고 빈 칸은 앞으로 채운다.
  특징은 학습·서비스 공통 전처리(`src/preprocess/`, 과제 8 계획) 위에서 만든다. 서비스가 같은 함수로 같은 특징을 만들 수 있어야 한다.

**분류기와 선택**

- **FR-030**: 후보 분류기: HistGradientBoosting(기본), 로지스틱 회귀, 작은 MLP(과제 7 변환 대상). 클래스 가중으로 불균형을 다룬다.
- **FR-031**: 학습은 학습 기간, 선택(후보·하이퍼파라미터·임계값)은 검증 기간만 쓴다. 선택 결과를 `selection.json`으로 고정한 뒤에만 시험·관찰 평가를 허용한다.
- **FR-032**: 환기 경보 임계값은 검증 재현율 ≥ 85%를 만족하는 값 중 정밀도 최대로 정한다. 사용 여부는 검증 macro-F1 최대 임계값으로 정한다.
- **FR-033**: 시험 기간 값을 바꿔도 선택·임계값·학습 결과가 같음을 자동 시험으로 확인한다.

**평가**

- **FR-040**: 사용 여부: 정확도·F1(사용중)·macro-F1·비어있음→사용중 오류율·혼동 행렬. 정답 기준은 관찰(있을 때)과 일정 기반 두 가지로 따로 낸다.
- **FR-041**: 환기 경보: 재현율·정밀도·F1·macro-F1·PR 곡선·혼동 행렬·하루당 헛경보·선행 시간 분포. "항상 음성"의 정확도를 함께 적는다.
- **FR-042**: 단순 규칙과 같은 시점·같은 지표로 비교하고 확인 기준 판정표를 자동으로 만든다.
- **FR-043**: 과제 3 예측 기반 환기 판정과 분류기를 같은 시점에서 비교한다(묶음이 있을 때).
- **FR-044**: 오류 분석: 상태 전환 뒤 경과 시간별 오류율, 시간대·공간별 오류, 인원 수별 재현율(관찰에 인원이 있을 때), 대표 사례 그래프.

**심화**

- **FR-050**: 처음 보는 공간 실험: 공간 하나를 학습·검증·정규화에서 빼고 그 공간을 평가한다. 세 공간을 모두 돌린다.
- **FR-051**: 회의실 노쇼·예약 없는 사용 규칙(시간 기준은 설정). 관찰 기록·실제 예약과 대조한 결과만 성능으로 보고한다. 추정 예약만으로는 순환 논리라 동작 예시로만 적는다.

**운영·재현**

- **FR-060**: 실행마다 설정·씨앗·데이터·정답·선택 해시와 장치를 기록한다. 같은 씨앗이면 같은 결과다.
- **FR-061**: 산출물은 `docs/deliverables/task5/`(두 분류기 성적표·혼동 행렬, 일정 기반 정답과 관찰의 차이, 많이 틀리는 상황 사례), 심화는 `docs/advanced/task5/`, 점검 문서는 `docs/tasks/task5-state-estimation.md`에 둔다.
- **FR-062**: 과제 8용으로 최종 분류기 두 개를 `var/state/bundle/`에 묶는다. `bundle.json`에는 모델 종류·파일, 입력 규약 버전, 특징 순서, 정규화, 임계값, 데이터 해시를 담는다.
  최종 분류기가 MLP면 과제 7이 TensorRT로 변환하고, 트리·선형 모델이면 변환하지 않는다(CPU 측정만).

### Key Entities

- **관찰 기록**: space_id, start, end(KST), state(occupied/empty), people(선택), observer, note
- **사용 여부 정답**: 공간, 칸, label, source(timetable/booking_estimated/booking_file/observation)
- **환기 정답**: 공간, 칸, label(positive/negative/exceeded), 30분 안 최대 CO₂, 첫 초과 시각
- **특징 표**: 공간, 칸, 특징 열(사용 여부용·환기용 묶음 구분), 입력 관측 비율
- **선택 파일**: 문제별 고른 분류기·하이퍼파라미터·임계값·검증 지표, 고정 시각·해시
- **평가 결과**: 문제 × 방법(분류기·규칙·과제 3 예측) × 정답 기준(관찰·일정) 지표, 혼동 행렬, 오류 분석 표
- **분류기 묶음**: 모델 파일, 특징 규약, 정규화, 임계값, 데이터 해시

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용 여부 분류기가 **직접 관찰 시간대 기준** 정확도·F1과 비어있음→사용중 오류율을 보고하고, F1이 단순 규칙(최근 15분 CO₂ +30ppm)보다 높다.
  관찰이 목표량(research R2)에 못 미치면 "판단 보류"와 진행률을 적는다.
- **SC-002**: 환기 경보 분류기의 시험 기간 재현율이 **85% 이상**이고, macro-F1이 단순 규칙(현재 CO₂ ≥ 850)보다 높다.
- **SC-003**: 두 분류기의 혼동 행렬과 "가장 많이 헷갈리는 경우" 상위 3개가 사례와 함께 설명된다.
- **SC-004**: 시험 기간 값을 바꿔도 선택·임계값·가중치가 같음을 자동 시험으로 보인다(누수 0).
- **SC-005**: 일정 기반 정답과 관찰의 불일치율이 공간별로 숫자로 나온다(관찰이 있는 공간).
- **SC-006**: 일정 입력을 넣은 사용 여부 모델이 관찰 기준에서 이득이 없거나 손해임을(또는 그렇지 않음을) 숫자로 보인다(해결할 것 2의 근거).
- **SC-007**: 학습·평가 전체가 보드에서 30분 안에 끝나고, 최대 메모리는 2GB 이하다.
- **SC-008**: 모든 결과표에 측정 조건(데이터 기간, 실데이터, 정답 출처, 분할, 관찰 시간, 장치, 전력 모드)과 해석이 붙는다(헌법 V·VII).

## Assumptions

- 학습·선택은 과제 2·3과 같은 `v1-provisional` 분할로 한다. 일정 기반 정답으로 학습한다. 관찰 정답은 평가에만 쓴다(양이 적고 실시간 기간에만 있음).
- 관찰은 사용자·팀이 2026-10-20 이후 수업일에 한다. 목표량은 research R2(공간별 수업일 2일 이상, 총 20시간 이상, 일정 경계 포함)다. 관찰 일정은 사용자가 정한다.
- 회의실 정답은 추정 예약이라 CO₂에서 나온다. 회의실의 일정 기반 평가는 순환 논리라 참고로만 쓰고, 회의실 판정은 관찰로만 한다.
- 환기 경보의 1,000ppm은 실내 환기 권고 수준으로 README를 따른다. 기준값은 설정에서 바꿀 수 있다.
- 냉난방 상태(xflow)는 2026-10-20부터만 있어 입력으로 쓰지 않는다.
- 학습 실행은 과제 3 실험이 끝난 뒤에 한다(GPU·메모리 공유). scikit-learn 분류기는 CPU로 돈다.
