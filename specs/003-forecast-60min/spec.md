# Feature Specification: 60분 예측 (과제 3)

**Feature Branch**: `003-forecast-60min`

**Created**: 2026-10-21

**Status**: Ready for plan

**Input**: User description: "과제 3. 60분 예측 (README '과제 3' 전체 + 심화 B 3개 전부). 실습실·사무실·회의실의 CO₂·온도를 60분 앞까지
5분 간격(12칸)으로 예측한다. 입력·출력 설계(과거 길이, 입력 정보, 한 번에 vs 반복, 값 vs 변화량), LSTM·GRU·TCN 3종,
과제 2 평가 기준(분할 v1-provisional, 평가 시점 파일, 관측 칸만, 학습 기간 정규화) 그대로, 확인 기준 3개, 공간별 오차 분석,
일정 정보의 가치, 심화(과거 길이 × 모델, 미래 정보 입력 — 회의실은 추정 예약, 처음 보는 공간 일반화).
GPU 권한은 요청 중이며 CPU로도 돌아가야 한다." (GPU 권한은 같은 날 받음)

## 배경: 과제 2에서 넘겨받은 것 (2026-10-21 기준)

- **분석용 시계열**: 공간 × 항목 × 5분 칸. 칸마다 관측 여부(`filled` 표시)와 사용 센서 수가 있다.
  - 대상 공간: 실습실(lab), 사무실(office), 회의실(meeting)
  - 항목: CO₂, 온도, 습도(습도는 입력으로만 쓴다)
- **분할 `v1-provisional`**(과제 3~6 공식 평가 기준)

| 기간 | 날짜(KST) | 용도 |
|---|---|---|
| 학습 | 2025-09-04 ~ 2026-03-31 | 가중치 학습, 정규화 통계 |
| 검증 | 2026-04-02 ~ 05-09 | 조기 종료, 하이퍼파라미터·입력 설계·모델 선택 |
| 시험 | 2026-05-27 ~ 07-22 | **최종 평가만**. 선택에 쓰지 않는다 |

- **평가 시점 파일**: `eval_points_v1-provisional`(289,277행, sha256 `2f878c11d09ab68d…`). 행 = (공간, 항목, 기준 시각 t0, 지평 h, 정답).
  과제 3은 이 파일의 행만 예측하고 같은 정답으로 채점한다. 입력·정답은 관측 칸만 쓴다는 규칙도 같다.
- **기준선(시험 기간 MAE)**: 모든 공간·항목·지평에서 "현재값 유지"가 1위다.

| 공간 | CO₂ 60분(전체 / 사용 시간대) | 온도 60분(전체 / 사용 시간대) |
|---|---|---|
| 실습실 | **83.9 / 212.1ppm** | 0.21 / 0.23℃ |
| 사무실 | 73.4 / 158.0ppm | 0.14 / 0.26℃ |
| 회의실 | 177.8 / 511.8ppm | 0.20 / 0.44℃ |

- **데이터 성질(과제 2 진단서)**
  - 자기상관이 매우 높다(실습실 CO₂ 5분 0.999, 1시간 0.909). 오차는 사용 시간대, 특히 수업 시작·점심에 몰린다.
  - 실습실은 고정 일과표에 즉시 반응한다(수업 시작 뒤 5분 안, 측정일의 99%). 사무실은 일과표와 덜 맞는다(점심 반응 37%).
  - 회의실은 10분 주기 센서 1대다. 5·15분 지평은 정답 관측이 부족해 평가 불가이고, **30·60분만 평가**한다. 회의 일정 자료가 없다.
  - 학습(가을·겨울)과 시험(초여름)의 계절이 다르다. 온도 수준이 학습 범위의 위쪽 끝이다.
- **일정 자료**
  - 실습실·사무실: 고정 일과표(평일 09:00 수업 시작, 11:30~13:00 점심, 18:00 퇴실, 한국 공휴일 제외). 과제 2 설정에 있다.
  - 회의실: **실제 예약 자료가 없다**(2026-10-21 사용자 확인). 심화 2는 과거 CO₂ 급상승에서 회의 시간을 추정한 **추정 예약**으로 실험한다.
- **실행 환경**: Jetson Orin Nano Super(25W 모드), RAM 7.3GB(CPU·GPU 공유), sudo 없음.
  - GPU: 2026-10-21 관리자가 계정을 `video`·`render` 그룹에 추가했다. Orin(연산 규격 8.7), 드라이버 595.78, CUDA 13.2.
  - 같은 날 측정: GRU(은닉 64, 배치 512, 길이 48) 학습 한 단계가 GPU 13ms, CPU 178ms로 **약 13배** 빠르다.
    GPU와 CPU의 출력·기울기 차이는 LSTM·GRU 1e-6 수준이고, 합성곱은 5.5e-4(GPU 근사 연산 TF32 때문)다.
  - 학습은 GPU로 하되, CPU로도 같은 결과(오차 범위 안)가 나와야 한다.

## 용어

| 용어 | 뜻 |
|---|---|
| 지평 h | 기준 시각 t0에서 몇 분 뒤를 맞히는가. 5·10·…·60분(12칸). 표에는 5·15·30·60분을 싣는다 |
| 과거 길이(lookback) | 모델이 보는 t0 이전 구간의 길이 |
| 한 번에 출력(direct) | 12칸을 한 번에 내놓는다 |
| 반복 예측(recursive) | 1칸씩 예측하고 그 예측을 다음 입력으로 넣어 12번 반복한다 |
| 값 예측 / 변화량 예측 | 목표가 y(t0+h)인가, y(t0+h) − y(t0)인가 |
| 미래에 알 수 있는 정보 | t0 시점에 이미 알려진 t0 이후의 정보. 시각·요일·공휴일·일과표·예약 |
| 사용 시간대 | 평일·공휴일 제외·08~19시(과제 2와 같음) |
| 추정 예약 | 회의실 CO₂ 급상승 구간에서 거꾸로 만든 "회의가 있었던 시간". 실제 예약이 아니다 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 기준선을 이기는 60분 예측 모델을 만든다 (Priority: P1)

분석가(팀원)는 과거 센서값과 시간 정보를 넣어 각 공간의 CO₂·온도를 60분 앞까지 5분 간격으로 예측하는 모델을 학습한다.
그리고 과제 2와 같은 시점·같은 정답으로 기준선과 비교한 표를 얻는다.

**Why this priority**: 과제 3의 확인 기준(CO₂ 60분 30% 개선, 온도 개선)이 여기서 판정된다. 나머지 분석은 모두 이 모델 위에서 한다.

**Independent Test**: 명령 하나로 학습 → 시험 기간 예측 → 비교표가 나온다. 표는 기준선 3종과 학습 모델이 같은 평가 시점 수를 가진다.

**Acceptance Scenarios**:

1. **Given** 분할 `v1-provisional`과 평가 시점 파일, **When** 모델을 학습하고 시험 기간을 예측하면, **Then** 평가 시점 파일의 모든 대상 행
   (회의실 5·15분 제외)에 예측값이 하나씩 생긴다. 평가 시점 파일의 해시가 기록된다.
2. **Given** 예측 결과, **When** 비교표를 만들면, **Then** 공간 × 항목 × 지평(5·15·30·60분)마다 기준선 3종과 학습 모델의 MAE가
   전체·사용 시간대로 나란히 나온다. 현재값 유지 대비 개선율(%)도 함께 나온다.
3. **Given** 실습실 CO₂, **When** 60분 MAE를 비교하면, **Then** 현재값 유지(83.9ppm)보다 **30% 이상 작다**(58.7ppm 이하).
   다른 공간과 사용 시간대도 같은 기준으로 판정해 표에 적는다.
4. **Given** 온도, **When** 60분 MAE를 비교하면, **Then** 대상 공간에서 현재값 유지보다 작다. 못 미치는 공간은 이유를 적는다.

### User Story 2 - 시험 기간을 학습·선택에 쓰지 않았음을 증명한다 (Priority: P1)

평가자는 모델의 성적이 시험 기간 정보 없이 만들어졌는지 확인하고 싶다.

**Why this priority**: 확인 기준 3번이며, 이를 어기면 모든 숫자가 무의미하다(헌법 V).

**Independent Test**: 시험 기간 값을 크게 바꾼 데이터로 학습·선택 과정을 다시 돌려도 학습된 가중치·선택된 설정·정규화 통계가 같다.

**Acceptance Scenarios**:

1. **Given** 학습 과정, **When** 시험 기간의 입력·정답 값을 임의로 바꾸면, **Then** 학습 손실 기록, 조기 종료 시점, 선택된 하이퍼파라미터,
   가중치가 바뀌지 않는다(같은 난수 씨앗 기준).
2. **Given** 모델 선택(입력 설계·과거 길이·모델 종류), **When** 선택 근거를 보면, **Then** 모두 검증 기간 오차이다. 시험 기간 오차는
   선택이 끝난 뒤 한 번만 계산된다.
3. **Given** 정규화, **When** 통계를 확인하면, **Then** 과제 2의 학습 기간 통계(`norm_v1-provisional`)와 같다.
4. **Given** 시험 기간 첫 시점, **When** 입력 구간이 검증·학습 기간에 걸치면, **Then** 그 과거 **입력**은 써도 된다(실제 운영과 같음).
   단, 그 값의 정답을 학습에 쓰지 않는다.

### User Story 3 - 입력·출력 설계를 근거와 함께 정한다 (Priority: P1)

분석가는 "과거를 얼마나 볼지, 무엇을 넣을지, 어떻게 출력할지"를 실험으로 정하고 이유를 쓴다.

**Why this priority**: README 해결할 것 1번이며, 생각해 볼 점 Q2(값 vs 변화량)의 답이 여기서 나온다.

**Independent Test**: 각 설계 비교가 **검증 기간** MAE 표로 나오고, 선택한 설계가 표에서 가장 좋거나 그렇지 않은 이유가 적혀 있다.

**Acceptance Scenarios**:

1. **Given** 과거 길이 후보(30분·2시간·하루), **When** 같은 모델로 비교하면, **Then** 검증 MAE 표와 선택 근거가 나온다.
2. **Given** 입력 정보 조합(센서값만 / +시간대·요일 / +공간 / +일정), **When** 비교하면, **Then** 정보별 기여(검증 MAE 차이)가 나온다.
3. **Given** 한 번에 출력 vs 반복 예측, **When** 비교하면, **Then** 지평별 오차 증가 모양의 차이가 나온다.
4. **Given** 값 예측 vs 변화량 예측, **When** 비교하면, **Then** 오차와 함께 "변화가 없을 때 현재값을 얼마나 잘 지키는가"가 나온다.

### User Story 4 - 공간별로 어디서 왜 틀리는지 분석한다 (Priority: P2)

운영자는 어느 공간에서 예측을 믿을 수 있고, 어느 공간·어느 순간에 틀리는지 알고 싶다.

**Why this priority**: README 해결할 것 4번과 생각해 볼 점 Q1·Q3이다.

**Independent Test**: 공간별·시간대별·일정 사건 전후별 오차 표와 대표 사례가 나온다.

**Acceptance Scenarios**:

1. **Given** 시험 기간 예측, **When** 공간별로 나누면, **Then** 공간 × 지평 오차와 그 공간의 데이터 성질(센서 수, 주기, 일정 반응률)이 나란히 나온다.
2. **Given** 오차, **When** 시간대·일정 사건(수업 시작, 점심, 퇴실, 주말) 전후로 나누면, **Then** 오차가 가장 큰 순간 상위 목록이 나온다.
3. **Given** 일과표로 설명되지 않는 급변(창문 개방 추정: 사용 중 CO₂가 짧은 시간에 크게 떨어짐), **When** 찾으면, **Then** 그런 구간의 오차를 따로 보고한다.
   창문 개방 여부는 데이터에 없으므로 "추정"으로 적는다.
4. **Given** 회의실, **When** 분석하면, **Then** 과거 센서값에 없는 정보(회의 시작·인원)가 무엇이고 어디서 얻을 수 있는지 적는다.

---

### User Story 5 - 일정 정보의 가치를 숫자로 답한다 (Priority: P2)

운영자는 "일정 정보를 넣으면 60분 예측 오차가 몇 ppm 줄어드는가"를 알고 싶다.

**Why this priority**: README 해결할 것 5번과 산출물 3번이다.

**Independent Test**: 일정 입력만 다른 두 모델(나머지는 같음)의 시험 MAE 차이가 공간별·지평별로 나오고, 결론 문장이 나온다.

**Acceptance Scenarios**:

1. **Given** 일정 포함 모델과 일정 제외 모델(같은 구조·같은 씨앗들), **When** 시험 기간을 비교하면, **Then** 공간 × 지평의 MAE 차이와
   여러 씨앗에 걸친 변동 폭이 나온다.
2. **Given** 차이, **When** 결론을 쓰면, **Then** "일정 정보를 넣으면 실습실 CO₂ 60분 예측 오차가 ○ppm(○%) 줄어든다" 형식의 문장이 나온다.
   차이가 씨앗 변동보다 작으면 "구별할 수 없다"고 쓴다.
3. **Given** 사용 시간대와 일정 사건 직후, **When** 따로 비교하면, **Then** 일정 정보가 주로 어느 순간에 기여하는지 나온다.

### User Story 6 - 심화(B): 과거 길이 × 모델 종류, 미래 정보, 처음 보는 공간 (Priority: P3)

분석가는 심화 실험 세 가지를 수행한다.

**Why this priority**: 심화 B 항목이다. 기본 확인 기준 판정 뒤에 한다.

**Independent Test**: 실험마다 표 하나와 결론 문단이 나온다.

**Acceptance Scenarios**:

1. **과거 길이 × 모델**: 과거 1·2·4시간 × LSTM·GRU·TCN 9조합의 **검증** MAE와 학습 시간·파라미터 수가 나온다.
   최적 조합을 검증 기준으로 고른 뒤, 그 조합의 시험 MAE를 한 번 낸다.
2. **미래 정보 입력**: t0 이후 60분 동안의 일과표·예약을 입력에 넣는 방법을 설계한다. 실습실·사무실은 일과표, 회의실은 추정 예약으로 시험한다.
   회의실 30·60분 오차가 미래 정보 없이 학습한 모델보다 개선되는지 보인다.
   - 추정 예약은 실제 CO₂에서 만든 것이므로 시험 기간에서는 **"예약을 완벽히 알았다면"의 상한**이다. 결과 표와 결론에 이 점을 명시한다.
   - 실제 예약 자료를 받으면 같은 형식의 파일로 교체해 다시 돌릴 수 있다.
3. **처음 보는 공간**: 세 공간을 하나씩 학습에서 완전히 빼고(학습·검증 모두) 남은 두 공간으로 학습한 모델로 뺀 공간을 예측한다.
   같은 공간을 포함해 학습한 모델과의 오차 차이, 그리고 현재값 유지와의 비교가 나온다.

### Edge Cases

- **입력 구간에 결측이 있는 시점**: 관측 칸 비율이 정해진 기준 미만이면 그 시점은 예측하지 못한 것으로 기록한다.
  해당 행은 기준선 비교에서 빼지 않고 "현재값 유지로 대체한 값"과 "예측 불가 수"를 함께 보고한다. 표의 평가 시점 수가 기준선과 같아야 하기 때문이다.
- **입력의 빈 칸 처리는 인과적이어야 한다**: 입력 구간의 빈 칸은 t0 이전 값만으로 채운다(직전 값 유지 + 빈 칸 표시).
  과제 2의 보간 칸은 뒤쪽 관측(미래)을 쓸 수 있으므로, 보간 끝점이 t0 이후인 칸은 입력에 쓰지 않는다.
- **회의실 10분 주기**: 입력의 절반이 "주기 안 직전값" 칸이다. 이 칸은 관측 여부 표시와 함께 넣는다.
- **공휴일·방학**: 일정 입력은 공휴일을 비수업일로 둔다. 방학은 고정 일과표가 모르므로 오차 분석에서 드러난다.
- **계절 이동**: 시험 기간 온도가 학습 범위 위쪽에 있다. 온도 성적이 기준선보다 나쁘면 계절 이동 때문인지 검증 기간과 비교해 적는다.
- **시험 기간 사건 구간**(밀집 등): 평가에 넣고, 따로도 보고한다(과제 2 결정).
- **GPU가 없거나 중간에 생김**: 같은 설정·같은 씨앗이면 장치와 관계없이 오차가 정해진 허용 범위 안에서 같아야 한다. 결과에 장치를 기록한다.
- **학습이 발산하거나 메모리가 부족함**: 실패를 기록하고 다음 실험으로 넘어간다. 실험 전체가 한 번의 실패로 멈추지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

**데이터와 평가 규칙(과제 2 승계)**

- **FR-001**: 학습·검증·시험 표본은 과제 2의 분석용 시계열과 분할 `v1-provisional`에서 만든다. 정규화는 과제 2의 학습 기간 통계를 그대로 쓴다.
- **FR-002**: 시험 평가는 평가 시점 파일의 행만 대상으로 한다. 시작 시 파일 해시를 확인하고 결과에 기록한다. 해시가 다르면 실행을 멈춘다.
- **FR-003**: 정답은 관측 칸만 쓴다. 학습 손실에서도 정답이 관측이 아닌 칸은 제외한다(가려서 계산).
- **FR-004**: 입력은 t0 이전 정보와 "미래에 알 수 있는 정보"만 쓴다. 입력의 빈 칸 채우기는 인과적이어야 한다(Edge Cases).
- **FR-005**: 시험 기간 정답·오차는 학습, 조기 종료, 하이퍼파라미터·입력 설계·모델 선택 어디에도 쓰지 않는다.
  시험 평가는 선택이 끝난 설정에 대해서만 실행한다. 이를 자동 시험으로 확인한다(US2).

**입력·출력 설계**

- **FR-010**: 입력 정보는 설정으로 켜고 끌 수 있어야 한다.
  - 센서값: CO₂·온도·습도와 칸별 관측 표시
  - 시간 정보: 시각(주기 표현), 요일, 공휴일 여부
  - 공간 표시
  - 일정: 현재 일정 상태와 미래 60분의 일정(미래에 알 수 있는 정보)
- **FR-011**: 과거 길이는 설정값이다. 기본 실험 후보는 30분·2시간·하루, 심화 실험은 1·2·4시간이다.
- **FR-012**: 출력 방식(한 번에 / 반복)과 목표(값 / 변화량)는 설정값이다. 두 축을 모두 비교한다.
- **FR-013**: 한 모델이 세 공간과 두 항목을 함께 다룰 수 있어야 한다(공간 표시 입력). 공간별 모델도 비교 대상으로 둘 수 있다.

**모델과 학습**

- **FR-020**: LSTM·GRU·TCN 세 종류를 같은 입력·출력 규약으로 학습할 수 있다. 모델 크기는 설정값이다.
- **FR-021**: 학습은 학습 기간 표본으로만 하고, 조기 종료와 선택은 검증 기간 오차로 한다.
- **FR-022**: 같은 설정을 여러 씨앗(기본 3개)으로 학습해 평균과 변동 폭을 보고한다. 비교 결론은 변동 폭을 넘는 차이일 때만 쓴다.
- **FR-023**: 실행마다 설정, 씨앗, 데이터·평가 시점 해시, 장치(CPU/GPU), 학습 시간, 파라미터 수, 가중치 파일 해시를 기록한다.
  기록만으로 같은 결과를 다시 만들 수 있어야 한다.
- **FR-024**: 학습·예측은 GPU가 있으면 쓰고 없으면 CPU로 동작한다. 메모리 사용은 보드에서 다른 서비스(수집기)와 공존할 수 있는 범위로 제한한다.

**평가와 분석**

- **FR-030**: 비교표는 기준선 3종 + 학습 모델(들)을 공간 × 항목 × 지평(5·15·30·60분)으로, 전체·사용 시간대 MAE와 현재값 유지 대비 개선율로 낸다.
  평가 시점 수는 기준선 표와 같다.
- **FR-031**: 확인 기준 판정표를 자동으로 만든다: CO₂ 60분 30% 개선(공간별), 온도 60분 개선(공간별), 누수 시험 결과.
- **FR-032**: 공간별 오차 분석: 공간 × 지평 × 시간대(일과 단계) 오차, 오차 상위 순간 목록, 일정 사건 전후 오차, 창문 개방 추정 구간 오차.
- **FR-033**: 일정 정보 가치: 일정 입력만 다른 두 설정의 시험 MAE 차이(씨앗 변동 포함)와 결론 문장.
- **FR-034**: 값 vs 변화량, 한 번에 vs 반복 비교 결과로 생각해 볼 점 Q2의 답을 낸다.

**심화(B)**

- **FR-040**: 과거 길이(1·2·4시간) × 모델(LSTM·GRU·TCN) 9조합의 검증 MAE, 학습 시간, 파라미터 수 표와 최적 조합(검증 기준)의 시험 MAE.
- **FR-041**: 미래 정보 입력 설계: 일정·예약을 "t0 이후 60분 구간의 칸별 상태"로 넣는다. 예약 자료는 설정의 파일 경로로 교체할 수 있다.
  회의실 추정 예약은 CO₂ 급상승 규칙(설정값)으로 만들고, 결과에 "추정 예약 = 상한"임을 표시한다.
- **FR-042**: 처음 보는 공간 시험: 공간 하나를 학습·검증 표본에서 모두 뺀 모델로 그 공간의 시험 시점을 예측한다. 세 공간을 모두 돌린다.

**운영·재현**

- **FR-050**: 모든 실험은 설정 파일과 명령으로 다시 실행할 수 있다. 실험 목록 전체를 한 명령으로 이어서 돌릴 수 있고, 중간에 끊겨도 끝난 실험은 다시 하지 않는다.
- **FR-051**: 산출물은 `docs/deliverables/task3/`(모델 비교표, 공간별 오차 분석, 일정 정보 포함·제외 비교), 심화 결과는 `docs/advanced/task3/`,
  점검 문서는 `docs/tasks/task3-forecast-60min.md`에 둔다. 표·그래프는 명령으로 다시 만들 수 있다.
- **FR-052**: 과제 4~8이 쓸 수 있게 최종 선택 모델의 가중치, 입력 규약, 정규화 통계를 한 묶음으로 저장한다(과제 7 최적화, 과제 8 서비스의 입력).

### Key Entities

- **실험 설정**: 모델 종류, 크기, 과거 길이, 입력 정보 조합, 출력 방식, 목표, 씨앗, 학습 공간 목록. 해시로 식별한다.
- **표본**: (공간, 기준 시각 t0) → 입력 구간(과거 센서값·관측 표시·시간·일정), 미래 정보, 정답 12칸과 정답 관측 표시.
- **실행 기록**: 실험 설정 해시, 씨앗, 장치, 학습 시간, 조기 종료 시점, 검증 MAE, 가중치 해시, 데이터·평가 시점 해시.
- **예측 결과**: 평가 시점 파일의 행마다 실행별 예측값. 기준선 결과와 같은 키로 이어 붙일 수 있다.
- **예약(일정) 자료**: 공간, 시작, 끝, 종류, 출처(일과표 / 실제 예약 / 추정 예약).
- **모델 묶음**: 최종 모델 가중치, 입력 규약, 정규화 통계, 설정. 과제 7·8로 넘긴다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 시험 기간 **실습실 CO₂ 60분 MAE가 58.7ppm 이하**(현재값 유지 83.9ppm 대비 30% 이상 개선)다. 사무실·회의실도 같은 기준으로 판정해 표에 적는다.
- **SC-002**: 시험 기간 **온도 60분 MAE가 현재값 유지보다 작다**(실습실 0.21℃, 사무실 0.14℃, 회의실 0.20℃ 미만).
- **SC-003**: 시험 기간 값을 바꿔 다시 학습해도 가중치·선택 결과·정규화 통계가 같음을 자동 시험으로 보인다(누수 0).
- **SC-004**: 비교표의 평가 시점 수가 기준선 표와 **같다**(행 단위 일치). 예측하지 못한 행 수가 따로 보고된다.
- **SC-005**: 일정 정보의 가치가 "○ppm(○%) 줄어든다" 또는 "씨앗 변동 안이라 구별할 수 없다"로, 씨앗 3개 이상의 변동 폭과 함께 답해진다.
- **SC-006**: 심화 실험 3개가 각각 표와 결론을 가진다. 과거 길이 × 모델은 9조합 모두 채운다.
- **SC-007**: 실험 전체(기본 + 심화)를 보드에서 사람 손 없이 이어서 돌릴 수 있다. GPU로 **하루(24시간) 안에** 끝난다. 중간에 끊겨도 이어서 돌릴 수 있다.
- **SC-008**: 학습 중 최대 메모리가 **2GB 이하**다(수집기와 공존).
- **SC-009**: 모든 결과표에 측정 조건(데이터 기간, 실데이터, 분할·평가 시점 해시, 장치, 전력 모드, 씨앗 수)과 해석이 붙는다(헌법 V·VII).

## Assumptions

- 과제 2의 분석용 시계열·분할·평가 시점 파일·정규화 통계를 그대로 쓴다. 과제 2를 다시 만들어도 평가 시점 해시가 같아야 한다(2026-10-21 확인).
- 대상은 CO₂와 온도다. 습도는 입력으로만 쓰고 예측·평가하지 않는다.
- 회의실은 5·15분 지평을 평가하지 않는다(과제 2와 같은 이유). 학습에서는 관측 정답이 있는 칸만 손실에 넣는다.
- 회의실 예약은 추정 예약으로 대신한다. 결과는 상한으로 해석한다. 실제 예약 자료가 생기면 파일만 바꿔 다시 돌린다.
- 실습실·사무실 일정은 고정 일과표다. 휴강·보강·행사는 반영되지 않는다(과제 2 진단: 어긋나는 날 실습실 24일).
- GPU 권한은 2026-10-21에 받았다. 그룹 권한은 새로 로그인한 프로세스부터 적용된다. 그 전에 띄운 셸·사용자 서비스에서는
  `sg video -c "sg render -c '<명령>'"`으로 실행하거나 다시 로그인한다.
- 냉난방 상태(xflow)는 2026-10-20부터만 있어 입력으로 쓰지 않는다.
- 2학기 시험(`v2-final`)은 InfluxDB 미적재분 적재 뒤 추가 비교로 할 수 있다. 이 spec의 판정은 `v1-provisional` 기준이다.
